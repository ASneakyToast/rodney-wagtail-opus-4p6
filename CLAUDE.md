# Rodney Wagtail Automation

## Automatic Startup (Claude Code on the web)

When a session starts, the SessionStart hook installs all dependencies (jq, Chrome, uv, rodney, showboat) and writes the `.env` file. **You should immediately begin the automation pipeline without waiting for user input.**

## Pipeline — Run These Steps In Order

### Phase 1: Discovery

Run the discovery phase to inspect the existing target page and auto-generate CSS selectors:

```bash
bash discovery/run-all.sh
```

This logs into the Wagtail admin, navigates to the target page (TARGET_PAGE_ID), inspects the edit form fields, discovers existing StreamField blocks and their types, finds the display_template field, and writes updated selectors to `config/selectors.sh`.

If discovery fails on a specific step, diagnose the issue from the output and screenshots, fix it, and retry that step individually (e.g., `bash discovery/03-inspect-page-form.sh`).

### Phase 2: Page Update

Run the update phase to edit the existing target page with new content:

```bash
bash update/run-all.sh
```

This navigates to the target page's edit form, audits existing blocks, sets the display template to "flexible template", updates basic fields (title, slug, SEO), clears existing body StreamField blocks, fills all sections from `data/design-strategy-mba.json`, and publishes.

If a step fails, check the screenshot in `screenshots/` for context. You can restart from a specific step (e.g., `bash update/06-clear-and-fill-body.sh`), but note that the browser session must still be active.

### Phase 3: Verification

Run verification scripts to confirm the page was updated correctly:

```bash
bash verify/verify-creation.sh
bash verify/verify-content.sh
bash verify/verify-published.sh
```

These generate Showboat markdown documents in `docs/` and screenshots proving the page was updated, content matches, and the page is live.

## Legacy: Create Workflow

The `create/` directory contains the original scripts that created a NEW child page. These are preserved for reference but should NOT be used for the current task. Use `update/` instead.

## Troubleshooting

- **Browser not started**: Run `uvx rodney start` to start headless Chrome.
- **Login fails**: Check `.env` credentials. The login page is at `${WAGTAIL_ADMIN_URL}/login/`.
- **Selector not found**: Re-run discovery phase — Wagtail may have updated its DOM structure.
- **StreamField block fails**: Check `screenshots/` for the latest state. The block chooser UI varies between Wagtail versions.
- **Step partially completed**: Check `uvx rodney url` to see current page state and `uvx rodney screenshot debug.png` to capture what the browser sees.
- **Display template not found**: The field may be on a different tab (Content, Settings, or Promote). Discovery step 03 searches all tabs.

## Key Files

| Path | Purpose |
|------|---------|
| `config/env.sh` | Loads and validates `.env` variables (requires `TARGET_PAGE_ID`) |
| `config/selectors.sh` | CSS selectors (auto-generated by discovery) |
| `lib/*.sh` | Reusable helper functions |
| `data/design-strategy-mba.json` | Content data for the page |
| `discovery/run-all.sh` | Full discovery pipeline (inspects existing page) |
| `update/run-all.sh` | Full update pipeline (edits existing page) |
| `create/run-all.sh` | Legacy: creates a new child page (do not use) |
| `verify/*.sh` | Verification scripts |
